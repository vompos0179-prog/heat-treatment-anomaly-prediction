# Team Workflow

## 권장 작업 흐름

### 1. Issue 생성
작업 목적과 완료 조건을 먼저 적습니다.

예:
- 제목: `[EDA] 정상/이상 온도 분포 비교`
- 목적: 정상과 이상에서 온도 분포가 다른지 확인
- 완료 조건:
  - 그래프 1개 이상
  - 기초 통계 비교
  - 관찰/해석 작성

### 2. 브랜치 생성

```bash
git checkout main
git pull
git checkout -b feature/eda-temperature
```

### 3. 작업 및 Commit

```bash
git add .
git commit -m "eda: 정상과 이상 온도 분포 비교"
git push -u origin feature/eda-temperature
```

### 4. Pull Request 생성

PR에는 반드시 아래를 작성합니다.

- 무엇을 했는가
- 왜 했는가
- 결과는 무엇인가
- 팀에서 결정해야 할 것은 무엇인가

### 5. 팀 검토 후 병합

처음 프로젝트에서는 코드 리뷰를 어렵게 생각하지 말고 다음만 확인합니다.

- 실행되는가?
- 분석 목적과 코드가 맞는가?
- 그래프가 질문에 답하는가?
- 결과 해석이 과장되지 않았는가?
- README/PPT에 반영할 가치가 있는가?

---

## 팀장 운영 제안

팀장은 모든 코드를 대신 작성하는 역할보다 다음을 담당합니다.

- 전체 분석 흐름 유지
- 중복 작업 방지
- 각 작업의 목적 확인
- 팀원이 이해하지 못한 분석이 그대로 진행되지 않도록 조정
- 결과 통합
- README/PPT 스토리 일치 여부 확인

---

## 회의 때 확인할 5가지

1. 지금 무엇을 확인하려는가?
2. 데이터로 확인 가능한가?
3. 결과는 무엇인가?
4. 다음 분석으로 어떻게 연결되는가?
5. 발표에서 한 문장으로 설명 가능한가?
