# Contributing Guide

이 저장소는 팀 프로젝트 협업을 위한 저장소입니다.

## 기본 원칙

1. 큰 작업은 Issue를 먼저 생성합니다.
2. `main`에서 직접 작업하기보다 작업 브랜치를 만듭니다.
3. 한 PR에는 가능한 한 하나의 분석 목적만 담습니다.
4. 코드만 올리지 말고 결과와 해석을 PR에 적습니다.
5. 병합 전에 최소 한 명의 팀원이 내용을 확인합니다.

## 브랜치 이름 예시

- `feature/data-check`
- `feature/preprocessing`
- `feature/eda-temperature`
- `feature/anomaly-window`
- `feature/model-baseline`
- `docs/readme`

## Commit 메시지

- `feat:` 기능/분석 추가
- `fix:` 오류 수정
- `data:` 데이터 처리
- `eda:` EDA
- `model:` 모델
- `viz:` 시각화
- `docs:` 문서
- `refactor:` 구조 개선

## PR에 반드시 적을 것

- 무엇을 했는가?
- 왜 했는가?
- 어떤 결과가 나왔는가?
- 결과를 어떻게 해석하는가?
- 설비 고장/이상 예측과 어떤 관련이 있는가?
- 팀원이 확인해야 할 부분은 무엇인가?
