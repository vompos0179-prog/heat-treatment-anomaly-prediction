# Project Guide

## 프로젝트 판단 순서

1. 평가 기준에 맞는가
2. 프로젝트 주제와 직접 연결되는가
3. 데이터로 확인 가능한가
4. 분석 목적이 명확한가
5. 결과를 설명할 수 있는가
6. 팀원이 이해하고 발표할 수 있는가
7. 불필요하게 복잡하지 않은가

## 분석 결과 작성 형식

### 분석 목적
왜 이 분석을 하는가?

### 사용 데이터
어떤 컬럼/구간을 사용하는가?

### 방법
어떤 방법을 사용했고 왜 선택했는가?

### 결과
숫자/그래프에서 무엇이 확인되었는가?

### 해석
관찰된 사실이 무엇을 의미하는가?

### 설비 관점
이 결과를 이상 탐지 또는 예지보전에 어떻게 연결할 수 있는가?

### 한계
현재 데이터만으로 말할 수 없는 것은 무엇인가?

## 사실과 가설 구분 예

- 관찰: 이상 구간에서 진동 값이 정상 구간보다 증가했다.
- 해석: 진동은 이상 상태를 구분하는 후보 변수일 수 있다.
- 가설: 특정 기계 부품의 마모가 원인일 가능성이 있다.
- 주의: 부품 마모 원인은 별도 정비 기록이나 설비 지식 없이 확정하지 않는다.
