#### 팀 코드에서 알아 둘 점 (고치지 않고 기록만)
1. **"이상 시간(sec)"은 사실 기록 수**다. 팀 `02`·`04`·`07`의 `*_sec` 열은 1초 기록 하나를 1초로 센 값이다. 실제 시각 기준 값은 ②의 `추가_` 파일에 따로 있다(기록 간격이 거의 1초라 두 값이 거의 같음 — 아래 2-3).
2. **팀의 "전체" 비율은 6개 센서를 합친 것**이고, 판정 가능한 기록도 "6개 센서 모두 값이 있는 기록"이다. 발표 주 결과(솔트조)는 ②의 설비별 파일을 쓴다.
3. **A1의 `max_abs_deviation`은 잔차 중심을 뺀 값**이다(물리 조건 판정에는 빼지 않은 값을 씀). 중심이 0에 가까워 차이는 작지만, 표에 "최대 이탈(℃)"로 쓸 때는 이 점을 적는다.
4. `max_score`·`max_abs_deviation`은 첫~마지막 후보 사이 **모든 기록**(후보가 아닌 기록 포함)에서 최댓값을 잡는다.
5. 06(불량률 상관)·07(월별) 파일도 만들어지지만 이 프로젝트에서는 쓰지 않는다(06은 요약 1장에 한 줄, 월별 표기는 6단계).

## 2. 발표 대비 자세한 설명

### 2-1. A1·A2를 쉬운 말로

| | A1 (주 결과) | A2 (비교) |
|---|---|---|
| "평소 온도" | **직전 10분** 같은 작업의 중앙값(지금 기록은 빼고 과거만) | **1~4월 전체**의 중앙값(고정) |
| 비유 | "방금 전까지의 나"와 비교 | "1~4월 평균적인 나"와 비교 |
| 장점 | 작업마다 운전 온도가 조금 달라도 그 작업 기준으로 봄 | 계산이 단순, 수준 자체가 달라진 것을 잡음 |
| 약점 | 천천히 바뀌면 기준도 따라가서 못 잡을 수 있음 | 운전 수준이 바뀐 달(1월 솔트조 약 329℃)을 통째로 이상으로 봄 |

세 조건을 **모두** 만족해야 이상으로 남는다.
1. **크게:** 흔들림 크기(1~4월로 정한 1.4826×MAD)의 4배 이상 벗어남(|Z| ≥ 4)
2. **실제로도 의미 있게:** 솔트조 0.3℃, 소입로 3℃ 이상 벗어남(학습 구간 척도로 설명하는 "분석용 최소 이탈 가정" — 규격 아님)
3. **오래:** 후보가 2초 이하 간격으로 이어져 60초 이상(팀 규칙: 마지막 − 첫 시각 + 1초)

> 숫자(4, 0.3℃/3℃, 60초)는 공유받은 팀 코드의 상수 그대로이며, **이번 재현·정리 과정에서 바꾸지 않았다.** 팀이 과거에 6~7월 결과를 보기 전에 이 값을 정했는지는 실행 기록이 없어 **확인되지 않았다**(계획 §2-1·§2-2). 앞으로는 이 값을 바꾸지 않는 것이 작업 원칙(C3)이다.
