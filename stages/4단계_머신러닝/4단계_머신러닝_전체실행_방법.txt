4단계 머신러닝 전체실행 — 10/8 추가 전달사항 반영 실행방법

============================================================
0. 이번에 달라진 핵심
============================================================

이제 4단계가 A1/A2 기록 단위 판정을 내부에서 다시 계산하지 않습니다.

3단계 ① 팀코드 재현본이 만든
검증용_기록라벨/*.npz
파일의 A1/A2 valid/qual을 직접 읽습니다.

그 다음:
- 현재 원본의 작업별 시각과 NPZ의 TAG_MIN_ns를 기록 하나하나 대조
- NPZ qual로 복원한 A1/A2 이벤트와
  3단계 ②의 03_A1_A2_이상이벤트.csv를
  시작시각/종료시각/길이/후보기록수까지 대조
- 일치해야 A1/A2/IF 비교 진행

이는 전달된 3단계 README와
3단계_공통범위_비교.py의 기록 단위 공통범위 정의를 반영한 것입니다.

2. 매우 중요 — 3단계 ① 재현본을 한 번 실행
============================================================

4단계의 기록 단위 비교에는
3단계 ① 재현본의 검증용_기록라벨/*.npz가 필요합니다.

프로젝트 맨 위에서:

cd <프로젝트 맨 위 폴더>

.\.venv\Scripts\python.exe "stages/3단계_이상구간/3단계_이상구간_팀코드재현.py"

중요:
--no-labels 옵션을 붙이면 안 됩니다.

정상 실행 후 예를 들어 아래와 같은 폴더가 생깁니다.

reports\3단계_이상구간_팀코드재현\20261019_112427_611588\

그 안에 반드시:

검증용_기록라벨\
    작업번호1.npz
    작업번호2.npz
    ...

가 있어야 합니다.

실행 후 생성된
20261019_112427_611588
같은 '폴더명'을 기억합니다.


============================================================
3. 3단계 ② 정리본 결과 확인
============================================================

3단계_이상구간_찾기.py의 완료 결과도 필요합니다.

예:
reports\3단계_이상구간\20261019_112613_665212\

그 안에 최소:

03_A1_A2_이상이벤트.csv
추가_설비그룹_이벤트.csv
추가_기간별_설비별_요약.csv

가 있어야 합니다.

현재 사용자 PC에서 이전에 확인된 정리본 폴더는:

20261019_112613_665212

입니다.

팀원 PC에서는 각자 실제로 존재하는 완료 폴더명을 사용하면 됩니다.


============================================================
4. 3단계_비교기준.txt 수정
============================================================

stages\4단계_머신러닝\3단계_비교기준.txt

를 엽니다.

형식:

재현본=①재현본폴더명
정리본=②정리본폴더명

예:

재현본=20261019_112427_611588
정리본=20261019_112613_665212

주의:
- C:\... 같은 전체 경로를 쓰지 않습니다.
- 따옴표를 쓰지 않습니다.
- reports\...도 쓰지 않습니다.
- 실행 폴더명만 적습니다.
- 재현본은 검증용_기록라벨 폴더가 있는 실행이어야 합니다.

6. 4단계에서 자동으로 확인하는 것
============================================================

[2단계 기준]
- 작업 첫 기록 월로 작업 전체의 기간을 결정
- 월 경계에서 작업을 둘로 나누지 않음
- 1~4월 / 5월 / 6~7월의 세 기간 작업 집합이
  3단계 기간 집합과 같은지도 확인

[3단계 ① 기록단위]
- NPZ 작업 목록 == 현재 원본 작업 목록
- NPZ TAG_MIN_ns == 현재 원본 TAG_MIN
- 솔트조 1·2 Zone A1/A2 valid/qual 직접 사용

[3단계 ② 이벤트]
- NPZ qual로 복원한 이벤트와
  03_A1_A2_이상이벤트.csv의
  배정번호/센서/시작/종료/길이/후보기록수 대조
- 불일치 시 비교 중단

[공통범위]
- 3단계_공통범위_비교.py와 같은 방식:
  설비 판정가능 = 솔트조 1·2 Zone 모두 valid
  설비 양성 = 솔트조 1·2 Zone 중 하나라도 qual
- 최종 A1/A2/IF 비교 =
  세 방법이 모두 판정 가능한 같은 6~7월 기록에서 수행

[G02 설비 단위]
- A1/A2 설비 구간:
  3단계 ② 추가_설비그룹_이벤트.csv를 그대로 사용
- IF:
  1·2 Zone 구간이 겹치거나 2초 이내면 설비 구간으로 합침

[Isolation Forest]
- 1~4월 학습
- 5월 99%, 99.5%, 99.9% 비교
- 99.9% 조건 고정
- 6~7월 재조정 없이 적용

============================================================
8. 3단계_공통범위_비교.py는 4단계 입력으로 필수인가?
============================================================

코드 파일 자체를 4단계가 직접 실행하거나 import하지는 않습니다.

하지만 그 코드의 공통범위 정의를 4단계에 동일하게 반영했습니다.

팀 전체 재현용으로는 실행할 수 있습니다:

cd <프로젝트 맨 위 폴더>

.\.venv\Scripts\python.exe "stages/3단계_이상구간/3단계_공통범위_비교.py" --ref1 재현본폴더명 --ref2 정리본폴더명

그러면:
reports\3단계_공통범위_비교\(실행시각)\
아래에

01_기간별_설비별_A1A2_공통범위비교.csv

등이 생성됩니다.

문제정의서 담당에게 전달하는 공통범위 표는 이 3단계 결과를 사용하면 됩니다.


============================================================
9. 다른 팀원이 처음 실행할 때
============================================================

1) 프로젝트 전체 폴더를 받음
2) 패키지 설치(맨 위 README 2절)
3) data/raw/data.csv와 src/data_contract.py 확인
4) 3단계 ② 정리본 결과가 있는지 확인
5) 3단계 ① 팀코드재현.py를 --no-labels 없이 한 번 실행
6) 생성된 ① 폴더명 확인
7) 3단계_비교기준.txt에 ①/② 폴더명 각각 입력
8) 4단계 머신러닝 전체실행.py 실행
9) reports/4단계_머신러닝/(실행시각)/완료.txt 확인

따라서 팀원이 바뀌어도 특정 개인 PC 절대경로에 의존하지 않습니다.


============================================================
10. 오류가 뜰 때
============================================================

[검증용_기록라벨이 없다고 뜸]
→ 3단계_이상구간_팀코드재현.py를
   --no-labels 없이 다시 실행

[재현본/정리본 폴더가 없다고 뜸]
→ 3단계_비교기준.txt에서 실제 폴더명 확인

[NPZ와 원본 시각이 다르다고 뜸]
→ 다른 원본/다른 3단계 실행을 섞은 것이므로
   해당 결과를 비교에 사용하지 말고 같은 프로젝트 원본으로 3단계를 다시 실행

[NPZ 이벤트와 ② 이벤트가 다르다고 뜸]
→ ①/② 결과 폴더가 서로 다른 버전일 가능성이 있으므로
   같은 팀 규칙으로 실행한 결과인지 확인

[정상 완료]
→ 결과 폴더에 완료.txt와 실행완료.txt가 생성됨
