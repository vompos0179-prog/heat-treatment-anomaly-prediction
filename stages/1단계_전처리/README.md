## 2. 발표 대비 자세한 설명

### ① `01_check_raw_data.py` — 원본 데이터 이해

전체 흐름에서의 위치: 데이터 이해 → 기본 품질 점검

분석을 시작하기 전에 "어떤 데이터가 얼마나 있고, 어떤 문제가 있는가?"를 확인하는 코드다.

| 중요한 코드 | 하는 일 | 사용한 이유 |
|---|---|---|
| `pd.read_csv(..., encoding="cp949")` | CSV를 표(데이터프레임)로 읽기 | 원본이 한글 Windows 형식(cp949)으로 저장되어 있음 |
| `dtype={"배정번호": "string"}` | 배정번호를 글자로 읽기 | 계산할 숫자가 아니라 작업 이름표이므로 |
| `df.shape`, `df.info()` | 행·열 수, 자료형 확인 | 데이터 크기와 구조 파악 |
| `df.isna().sum()` | 칸별 빈 값 개수 | 빈 값이 어느 센서에 몰리는지 확인 |
| `df.duplicated().sum()` | 모든 칸이 똑같은 줄 개수 | 같은 기록이 두 번 들어갔는지 확인 |
| `describe()` | 평균·최솟값·최댓값 등 | 센서값 범위를 대략 파악 |

확인한 결과
- 전체 2,939,722행, 21개 칸(시각 1, 배정번호 1, 센서 19), 배정번호(작업) 136개
- 완전히 같은 줄(중복) 0개
- 센서 빈 값 합계 6,043칸, 그중 `소입1존 OP`가 4,288칸
- 솔트조 온도 1·2 Zone 빈 값 209 / 203칸

해석 주의: 6,043은 "빈 값이 있는 줄 수"가 아니라 "센서별 빈 칸을 모두 더한 수"다. 한 줄에서 센서 3개가 비면 3으로 센다.

결과 파일: `raw_check_report.txt`

### ② `02_check_time_series.py` — 시간 구조 점검

전체 흐름에서의 위치: 데이터 이해 → 시간 기준 정하기

"시간이 제대로 읽히는가?", "정말 1초마다 기록되는가?", "기록이 끊긴 곳이 있는가?"를 확인한다.

| 중요한 코드 | 하는 일 | 사용한 이유 |
|---|---|---|
| `pd.to_datetime(..., errors="coerce")` | 글자로 된 시각을 시간 값으로 바꿈. 실패하면 빈 시간(`NaT`)으로 표시 | 시간 계산이 되는지 확인하고 실패 건수를 셈 |
| `groupby("배정번호")` | 작업별로 나누기 | 서로 다른 작업 사이의 시간을 이어 붙이지 않기 위해 |
| `sort_values()` | 작업 안에서 시간순 정렬 | 시간 차이를 순서대로 계산 |
| `diff().dt.total_seconds()` | 바로 앞 기록과 몇 초 차이인지 계산 | 기록 간격과 끊긴 곳 찾기 |
| `duplicated("_time")` | 같은 작업에 같은 시각이 두 번 있는지 | 중복 기록 점검 |

확인한 결과
- 시간 변환 실패 0, 배정번호 빈 값 0, 시간이 거꾸로 가는 곳 0, 같은 시각 중복 0
- 136개 작업 모두 가장 흔한 간격이 1초
- 기록 간격: 1초 2,877,840번(97.90%), 2초 61,643번(2.10%), 3~12초 100번, **60초가 넘는 공백 3번**(122초, 160초, 1,441초)
- 공백 위치: 작업 134495(5/13 17:29:58 → 17:32:00), 136014(5/20 17:16:56 → 17:40:57, 18:35:28 → 18:38:08)

해석 주의: 이 코드의 "결측 구간 904개"는 기록 간격이 1초를 넘으면 구간을 나누는 규칙으로 만든 숫자다. "빈 값 사건이 904번 일어났다"고 발표하면 안 된다.

### ③ `03_review_missing_context.py` — 빈 값·공백 앞뒤 살펴보기

전체 흐름에서의 위치: 전처리 기준 정하기 → 대표 사례 확인

②에서 찾은 빈 값·공백 앞뒤 5분 동안 센서들이 어떻게 움직였는지 확인한다. 5분은 "보는 범위"일 뿐 5분 평균을 내는 것이 아니다.

| 중요한 코드 | 하는 일 | 사용한 이유 |
|---|---|---|
| `pd.read_csv(..., chunksize=200000)` | 원본을 20만 줄씩 나눠 읽기 | 큰 파일을 읽을 때 메모리 부담을 줄임 |
| `isin(needed)` | 필요한 작업만 골라 남기기 | 검토할 데이터만 보관 |
| `pd.Timedelta(minutes=5)` | 앞뒤 5분 범위 정하기 | 사례마다 같은 범위로 비교 |
| `plot(..., linestyle="none")` | 기록을 점으로만 표시 | 기록이 없는 공백을 선으로 잇지 않기 위해(없는 값을 있는 것처럼 보이지 않게) |
| `axvspan()` | 검토 구간에 색 칠하기 | 빈 값·공백 위치를 눈에 띄게 |

전체 흐름에서의 위치: 데이터 이해 → 전체 모양 소개

| 중요한 코드 | 하는 일 | 사용한 이유 |

### ⑤ `src/data_contract.py` + `1단계_전처리_데이터계약점검.py` — 공통 읽기 규칙 (10/1 추가)

전체 흐름에서의 위치: 전처리 → **다음 모든 단계의 출발점**

①~④는 "확인용"이라 코드마다 원본을 따로 읽는다. 2단계부터는 여러 사람이 코드를 나눠 쓰므로, 모두 같은 규칙으로 읽도록 공통 함수를 만들었다. 비유하면 "모든 팀원이 같은 자로 길이를 재게" 만든 것이다.

공통 함수 (`src/data_contract.py`)

| 함수 | 하는 일 | 사용한 이유 |
|---|---|---|
| `load_raw(열 목록, 'float32' 또는 'float64')` | 시각·배정번호와 필요한 센서 열만 읽기. 시각 형식이 다르거나 빈 시각이 있으면 바로 멈춤 | 필요 없는 열을 안 읽어 빠르고, 잘못된 시각을 조용히 넘기지 않기 위해 |
| `add_segments(df)` | 작업별 시간순 정렬, 앞 기록과의 간격(`dt_prev`), 다음 기록까지의 간격(`dt_next`), 60초 넘게 끊긴 곳에서 구간(세그먼트) 나누기 | 끊긴 앞뒤를 이어서 계산하지 않기 위해. 시간 길이는 줄 수가 아니라 실제 시각 차이로 재기 위해 |
| `load_quality()` | 품질 파일을 읽고 배정번호를 원본과 같은 글자 형식으로 맞춤, 작업일의 월로 기간(학습 1~4월 / 조정 5월 / 후속 적용 6~7월) 붙이기 | 원본과 품질 파일을 정확히 연결하고 기간 나누기 기준을 하나로 통일 |

자주 나올 말 풀이
- **세그먼트**: 한 작업 안에서 60초 넘게 기록이 끊기면 그 앞과 뒤를 다른 구간으로 본다. 136개 작업 + 긴 공백 3번 = 139개 구간.
- **`dt_prev` / `dt_next`**: 기록 하나를 기준으로 "앞 기록과 몇 초 떨어졌나" / "다음 기록까지 몇 초인가". 이상 시간을 잴 때는 `dt_next`를 더한다(예: 0초·1초·3초 기록에서 1초 기록이 이상이면 이상 시간은 1초가 아니라 2초).
- **float32 / float64**: 숫자를 저장하는 정밀도. 팀원 결과를 똑같이 재현할 때는 팀원과 같은 float32를 쓴다. 차이는 최대 0.00003℃ 정도로 아주 작다.

점검 코드가 하는 일
1. 작은 가짜 데이터로 함수가 맞게 동작하는지 먼저 시험(0·1·3초 예제, 빈 시각 거부)
2. 원본 전체를 공통 함수로 읽기
3. 01·02 결과와 숫자 30가지 대조 — 하나라도 다르면 "실패"로 멈춤

확인한 결과
- 30가지 모두 일치: 2,939,722행, 작업 136개, 빈 값 수, 간격 분포, 긴 공백 3곳, 구간 139개, 품질 파일과 136개 작업 1:1 연결, 작업일 월별 작업 수 14·8·23·33·22·22·14
- 참고: 첫 기록 월로 세면 14·8·**22·34**·22·22·14. 차이는 작업 124532 하나(작업일 3/31, 첫 기록 4/1 새벽)뿐이고, 어느 기준이든 학습 기간(1~4월)이라 **기간 나누기 결과는 같다.**

해석 주의
- 긴 공백은 "설비가 멈췄다"는 뜻이 아니다. 기록이 없어 알 수 없을 뿐이다.
- 기간 6~7월은 팀이 이미 살펴본 기간이라 "최종 검증"이 아니라 "탐색적·회고적 비교"라고 부른다.
