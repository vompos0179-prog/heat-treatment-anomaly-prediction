## 1. 먼저 알아 둘 이야기 — 우리가 가진 데이터

### 1-1. 데이터는 "1초마다 온도를 적은 아주 긴 공책"

공장에는 쇠를 뜨겁게 달궜다가 식히는 **열처리** 기계가 있습니다.
기계 안 여러 곳에 **온도계(센서)** 가 붙어 있고, 컴퓨터가 **거의 1초마다** 온도를 공책에 적었습니다.

| 공책의 모습 | 실제 데이터 |
|---|---|
| 공책 이름 | `data/raw/data.csv` |
| 줄 수 | **2,939,722줄** (약 294만 줄 — 1초에 한 줄이면 약 34일 치) |
| 칸 수 | **21칸** = 시각 1칸 + 작업 번호 1칸 + 온도계 등 센서 19칸 |
| 기간 | 2022년 1월 ~ 7월 |
| 작업 수 | **136개** (작업마다 `배정번호`라는 이름표가 붙어 있음) |

- **배정번호** = 작업 이름표. "오늘 3번째로 한 일"처럼 작업 하나하나를 구별하는 번호입니다.
- **솔트조** = 뜨거운 소금물 통. 우리 분석의 **주인공** 온도입니다.
- **소입로** = 쇠를 달구는 화로. 비교용으로 함께 봅니다.

### 1-2. 우리가 지킨 약속 세 가지

1. **공책을 절대 고치지 않는다.** (원본 파일은 읽기만 함)
2. **빈칸을 지어내서 채우지 않는다.** 빈칸은 "모름(판정 불가)"으로 둡니다.
   - 빈칸을 앞뒤 숫자로 대충 채우는 것을 **보간**이라고 하는데, 팀 회의에서 **하지 않기로** 정했습니다.
3. **아직 "이상하다/정상이다"를 판정하지 않는다.** 1단계는 공책 상태 검사만 합니다.

## 2. 실행하는 방법

터미널(PowerShell)을 열고 **프로젝트 맨 위 폴더**(`README.md`·`stages/`·`src/`가 있는 폴더)에서 아래 한 줄을 입력합니다.

```powershell
python "stages/1단계_전처리/1단계_전처리_전체실행.py"
```

- `python` = 패키지(`requirements.txt`)를 설치한 파이썬(코드를 읽어 실행해 주는 프로그램). 맨 위 README대로 가상환경을 만들었다면 `.\.venv\Scripts\python.exe`를 씁니다.
- 따옴표 안 = 실행할 코드 파일 위치 (이름에 한글이 있어 따옴표로 감쌉니다)
- 걸리는 시간: 약 **5분**(검사마다 1분 안팎). 화면에 `▶ 1_원본확인 시작` … `■ 5_데이터계약 끝` 이 차례로 나옵니다.
- 코드가 맨 처음에 Python·패키지 버전을 확인합니다(`src/env_check.py`). 권장 버전(Python 3.12, `requirements.txt`)과 다르면 `[주의]`로 무엇이 다른지 알려 주고 **계속 실행**합니다.
  엑셀 파일을 읽는 부품(`openpyxl`)이 없으면 5번 검사에서 멈추므로, `[주의]`에 "설치되지 않음"이 보이면 먼저 `python -m pip install -r requirements.txt`를 실행하세요.
  - VS Code ▶(실행) 버튼을 쓰려면: **파일 → 폴더 열기**로 프로젝트 맨 위 폴더를 열고, `Ctrl+Shift+P` → `Python: Select Interpreter`에서 패키지를 설치한 파이썬을 고릅니다.
  - 화면 출력이 한글 Windows 기본 방식(cp949)이어도 멈추지 않습니다. 표현할 수 없는 기호(예: `−`)만 화면에서 `?`로 보이고, 보고서 파일에는 제대로 저장됩니다.
- 맨 마지막에 **`[완료] 1단계 전처리 전체 실행이 끝났습니다.`** 가 나오면 성공입니다.
- `[실패]`가 나오면 숫자가 기대값과 달라졌다는 뜻이니 **다음 단계로 넘어가지 마세요.**

### 0. 공통 설정 — 준비물 챙기기

```python
PROJECT = Path(__file__).resolve().parents[2]
```

- 왜 이렇게? 터미널을 어느 폴더에서 열었든 **항상 같은 공책을 찾게** 하려고요.

```python
LONG_GAP_SEC = 60
```

- "60초보다 오래 기록이 끊기면 **긴 공백**으로 본다"는 약속입니다.

### 공통 데이터 계약 — 모두가 쓰는 같은 자

**비유**: 반 친구들이 각자 다른 자로 키를 재면 숫자가 제각각이겠죠? 그래서 **모두 같은 자**를 쓰기로 약속한 것이 "데이터 계약"입니다.
2단계부터는 여러 사람이 코드를 나눠 짜므로, 모두 이 규칙으로 공책을 읽습니다.

| 일꾼 | 하는 일 | 왜 필요한가 |
|---|---|---|
| `load_raw(열 목록, 'float64')` | 시각·배정번호와 **필요한 칸만** 읽음. 시각이 이상하거나 비어 있으면 **바로 멈추고 알려 줌** | 잘못된 시각을 모르고 넘어가면 계산이 몰래 틀어지니까 |
| `add_segments(df)` | 작업마다 시간순으로 줄 세우고, 앞뒤 기록 사이 간격을 재고, 60초 넘게 끊긴 곳에서 **구간을 나눔** | 끊긴 앞과 뒤를 이어서 계산하면 안 되니까 |
| `load_quality()` | 품질 파일(불량 개수 표)을 읽고 작업마다 기간(1~4월 학습 / 5월 조정 / 6~7월 비교)을 붙임 | 기간 나누는 기준을 하나로 통일하려고 |

새로 나오는 말:
- **세그먼트(구간)**: 한 작업 안에서 60초 넘게 끊기면 앞과 뒤를 다른 구간으로 봅니다. 작업 136개 + 긴 공백 3번 = **구간 139개**.
- **`dt_prev`**: "바로 앞 기록과 몇 초 떨어졌나". **`dt_next`**: "다음 기록까지 몇 초 남았나".
  - 예: 0초, 1초, 3초에 기록이 있을 때 1초 기록의 `dt_prev`는 1초, `dt_next`는 2초입니다.
  - 나중에 "이상한 시간이 몇 초 동안이었나"를 잴 때 **줄 수가 아니라 `dt_next`를 더합니다.** 줄 하나가 항상 1초는 아니기 때문이에요.
- **float32 / float64**: 숫자를 저장하는 "자의 눈금 촘촘함". float64가 더 촘촘합니다. 둘의 차이는 최대 약 **0.00003℃** 로 아주 작습니다.

> 이 세 일꾼은 `src/data_contract.py`에 있는 것과 **글자 하나까지 똑같은 복사본**입니다.
> 한쪽만 고치면 안 되니까, 검사 ⑤가 시작할 때 "둘이 똑같은지"를 자동으로 확인합니다.
> 일꾼의 글자뿐 아니라 일꾼이 쓰는 **약속 값**(60초 기준, 월→기간 표, 칸 이름, 시각 모양, 공책 위치, 한글 방식)까지 모두 비교합니다.
> 비유: 자의 모양만 같고 눈금 간격이 다르면 소용없으니, 눈금까지 맞춰 보는 것입니다.

### 2. 시간 점검 — 출석부 시간 확인 (`step2_time_check`)

**비유**: 출석부에 "9시 00분 00초, 9시 00분 01초, …"처럼 1초마다 도장이 찍혀 있어야 하는데, 정말 그런지 확인합니다.

| 중요한 코드 | 쉬운 뜻 |
|---|---|
| `pd.to_datetime(...)` | "2022-01-03 08:00:00" 같은 **글자**를 컴퓨터가 계산할 수 있는 **시각**으로 바꿈 |
| `groupby("배정번호")` | 작업별로 나누기 (다른 작업끼리 시간을 이어 붙이지 않으려고) |
| `sort_values(...)` | 시간순으로 줄 세우기 |
| `diff()` | 바로 앞 기록과 몇 초 차이인지 계산 |

**알아낸 것**
- 시각을 못 읽은 줄 0, 시간이 거꾸로 가는 곳 0, 같은 시각이 두 번 적힌 곳 0
- 기록 간격: 1초 **2,877,840번(97.90%)**, 2초 61,643번(2.10%), 3~12초 100번
- **60초 넘게 끊긴 곳은 딱 3번**: 122초, 1,441초(약 24분), 160초
  - 작업 134495: 5월 13일 17:29:58 → 17:32:00
  - 작업 136014: 5월 20일 17:16:56 → 17:40:57, 18:35:28 → 18:38:08

⚠️ 이 검사 결과의 "결측 구간 904개"는 빈칸을 나누는 규칙 때문에 생긴 숫자입니다. "빈칸 사건이 904번 일어났다"고 말하면 안 돼요.

### 3. 결측·공백 검토 — 빈칸 주변 돋보기 (`step3_missing_review`)

**비유**: 공책에서 빈칸이나 찢어진 곳을 찾으면, 그 **앞뒤 5분** 동안 다른 온도들이 어땠는지 돋보기로 살펴봅니다.

| 중요한 코드 | 쉬운 뜻 |
|---|---|
| `chunksize=200000` | 큰 공책을 20만 줄씩 나눠 읽기 (컴퓨터 기억 공간 아끼기) |
| `isin(needed)` | 살펴볼 작업만 골라 남기기 |
| `pd.Timedelta(minutes=5)` | "앞뒤 5분"이라는 범위 정하기 |
| `plot(..., linestyle='none')` | 점만 찍고 **선으로 잇지 않기** — 없는 값을 있는 것처럼 보이지 않게 |
| `axvspan(...)` | 빈칸·공백 위치에 주황색 칠하기 |

**알아낸 것** (사례 8개: 빈칸 5개 E01~E05 + 긴 공백 3개 E06~E08)
- E01~E03: `소입1존 OP` 칸이 비어 있는 동안에도 **다른 18개 센서는 계속 기록됨** → 기록 전체가 끊긴 건 아님. 하지만 기계가 실제로 멈췄는지는 운전 기록이 없어서 **알 수 없음**
- E04: 작업 **시작부터** 비어 있어서 앞쪽 값이 없음 → 앞뒤로 채우는 방법(보간)을 쓸 수도 없는 사례
- E05: 2줄짜리 짧은 빈칸이지만 앞뒤에도 빈칸이 이어짐
- E06~E08: 긴 공백 앞뒤 값이 다르지만, 기록이 없는 동안 무슨 일이 있었는지는 **알 수 없음**

### 4. 5분 개요 — 멀리서 보는 사진 (`step4_overview`)

**비유**: 294만 줄을 한 장에 그리면 너무 빽빽하니까, **5분씩 묶어 평균**을 내서 7개월을 한 장의 "멀리서 찍은 사진"으로 만듭니다.

|---|---|
